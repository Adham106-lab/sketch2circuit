# Gerber File Structural Diagnostic Panel & Silkscreen Anomaly Inspector

A dedicated structural diagnostic panel in the **Export** tab that parses generated RS-274X Gerber and Excellon drill files, audits aperture tables for redundancy, analyzes vector stroke paths across silkscreen layers, and surfaces root-cause explanations for layer file size anomalies.

### User Review & Critical Decisions

> [!IMPORTANT]
> Because interactive clarification was skipped, the implementation will apply standard industry-practice EDA defaults: non-destructive structural inspection, per-layer size and token auditing, duplicate aperture detection, and silkscreen stroke vectorization breakdown.

- **Diagnostic Metrics**: Layer file sizes in bytes and line counts, total and unique aperture definitions (`%ADD...%`), aperture usage frequencies (`D10`–`Dnn`), primitive counts (flashes `D03`, line moves `D02`, draws `D01`, chained tracks), and silkscreen stroke count breakdown (courtyards, glyph strokes, silkscreen primitives).
- **Placement & UX**: Embedded directly beneath the Gerber file selector and metrics bar in the `Export` tab's Gerber view as an expandable **"Structural Diagnostics & Anomaly Inspector"** drawer.
- **Root-Cause Telemetry for `blink.gto`**: Dedicated explanation card for the top silkscreen layer explaining why vector-stroked font glyphs and 24-segment circle approximations scale character lines in pure Gerber RS-274X versus bottom silkscreen (`.gbo`), confirming compliance with Ucamco Gerber Spec §4.1/§4.2 and checking for duplicate aperture or redundant line bugs.

### 1. Overview & Core Concept

- **What It Does**: Inspects all 8 files generated by `@s2c/export-gerber` (`.gtl`, `.gbl`, `.gts`, `.gbs`, `.gto`, `.gbo`, `.gko`, `.drl`). It computes AST/token-level structural metrics for each layer: file size (bytes & lines), aperture definitions, duplicate aperture geometries, draw versus flash operations, and character/geometry stroke counts in silkscreen layers.
- **Target Audience / Persona**: Hardware engineers, PCB layout designers, and fab engineers who need to verify that exported Gerber packages contain clean aperture dictionaries without redundant definitions or bloat before fab upload.
- **Key Value**: Instantly de-mystifies why silkscreen layers (`.gto`) are larger than copper or mask files by breaking down vector strokes and validating that no duplicate apertures or redundant drawing loops exist in the generator.

### 2. User Experience & Visual Design

- **Key User Flows**:
  1. *View Export Tab*: In `ExportArtifacts`, navigating to the **Gerbers** tab renders the standard Gerber viewer alongside a new **Structural Diagnostics** toolbar toggle.
  2. *Inspect File Breakdown*: The diagnostic panel presents a multi-layer comparison table showing:
     - File Name & Layer Type
     - Byte Size & Line Count
     - Defined Apertures & Duplicate Warnings
     - Draw (`D01`) / Move (`D02`) / Flash (`D03`) Primitive Distribution
     - Health Status (Clean / Warning / Anomaly)
  3. *Silkscreen Deep-Dive Inspection*: Selecting `.gto` or clicking an anomaly flag opens the **Silkscreen Vector Inspector**, which categorizes strokes into:
     - Component RefDes Glyphs (vector font stroke segments)
     - Board-Level Silkscreen Text (stroke segments per character)
     - Footprint Outlines & Courtyards
     - Approximate Arc/Circle Polygon Segments
  4. *Aperture Table Audit*: Shows all `%ADDnn...%` definitions, checking if any apertures share identical dimensions or parameter definitions (e.g. redundant `%ADD10C,0.150000*%` declarations).

- **Visual Identity & Theme**:
  - *Aesthetic Direction*: Utilitarian developer & hardware engineering console adhering to the dark slate industrial palette of the existing application.
  - *Color Palette & Tokens*: Dark slate surfaces (`--bg-panel`, `--bg-subpanel`, `--bg-sunken`), amber warning accents for anomalies (`#f59e0b`), emerald for verified clean rules (`#10b981`), and cyan for vector stroke inspection.
  - *Typography & Hierarchy*: Strict tabular numerals (`font-mono tabular-nums text-xs`) for all byte sizes, line numbers, coordinate bounds, and counts. Section kickers in natural title case with quiet typographic separators (`·`). Zero pill capsules.
  - *Component Styling*: Single-elevation flat panels with hairline borders (`border border-neutral-800`), clean table row highlights, and collapsible disclosure carats.

- **Interactive Feedback & Motion**:
  - Instant client-side parsing without background latency ($\le 50\text{ms}$ calculation).
  - Smooth disclosure animation for deep-dive drawers with zero layout shifts.

### 3. Key Product Decisions & Trade-Offs

- **Decision 1: Client-Side Deterministic Parser vs. Regex Heuristics**
  - *Chosen Approach*: Implement a lightweight, robust Gerber AST parser in `packages/export-gerber` (`analyzeGerberStructure`) that tokenizes Gerber commands (`%ADD...%`, `Dnn*`, `X...Y...D01/02/03*`) directly from the generated string buffers.
  - *Why*: Provides exact primitive and aperture counts with 100% determinism across browsers and tests, and allows automated unit testing in Vitest.
  - *Alternatives Considered*: Regex counting on raw strings (brittle to formatting changes and misses duplicate aperture parameter hashing).

- **Decision 2: Integration Architecture**
  - *Chosen Approach*: Export `analyzeGerberStructure` and `GerberStructureAnalysis` types from `@s2c/export-gerber`, and consume them in a dedicated `GerberDiagnosticsPanel` component rendered inside `ExportArtifacts.tsx`.
  - *Why*: Keeps Gerber domain parsing logic inside the `@s2c/export-gerber` package with comprehensive test coverage, while keeping UI rendering modular and maintainable.

#### Data Model & State

```typescript
export interface ApertureDefinition {
  dCode: number;
  shape: "C" | "R" | "O" | "M";
  params: string;
  usageCount: number;
}

export interface DuplicateApertureWarning {
  shape: string;
  params: string;
  dCodes: number[];
}

export interface LayerStructuralAnalysis {
  filename: string;
  layerKind: "copper" | "soldermask" | "silkscreen" | "outline" | "drill";
  side: "top" | "bottom" | "both";
  byteSize: number;
  lineCount: number;
  apertureCount: number;
  apertures: ApertureDefinition[];
  duplicateApertures: DuplicateApertureWarning[];
  primitives: {
    flashes: number;      // D03
    draws: number;        // D01
    moves: number;        // D02
    tracks: number;       // multi-point linear interpolations
  };
  silkscreenMetrics?: {
    estimatedGlyphStrokes: number;
    estimatedGeometryStrokes: number;
    textCommandCount: number;
    strokeEfficiencyRatio: number;
  };
  warnings: string[];
}

export interface GerberStructureReport {
  timestamp: string;
  totalByteSize: number;
  layers: Record<string, LayerStructuralAnalysis>;
  hasDuplicateApertures: boolean;
  hasExcessiveSilkscreenVectors: boolean;
  sizeRatioGtoToGbo: number;
}
```

#### Interactive Component & State Mapping

1. **Diagnostic Drawer Toggle**: Allows toggling between collapsed quick-metrics and full structural inspection table.
2. **Layer Filter Selection**: Clicking any row in the diagnostic table synchronously switches the active Gerber file preview in `ExportArtifacts`.
3. **Silkscreen Deep-Dive Expansion**: Specifically highlights `.gto` vs `.gbo` comparison, verifying that the 12 KB `.gto` size is driven by vector stroke segments (5–7 segments per character) for RefDes and board title texts rather than duplicate aperture definitions or infinite loops.
4. **Automated Unit Testing**: Vitest test suite in `packages/export-gerber/test/analyzer.test.ts` validating duplicate aperture detection, stroke counting, and report generation against real exported test layouts.
